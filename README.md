## 项目介绍

跳槽是一个信息不对称的博弈：Offer 上的月薪不是真实收入，HR 报的 N 不是法定下限，年终奖多发一元可能少拿一千。这些账**本来都能算清**，只是散落在个税税率表、《劳动合同法》第 47 条、各地社平工资口径和你的公积金比例里。

打工人决策台把它们收敛成八个模块，**全部在浏览器本地计算**，不联网、不上传、不留痕。

## 目标用户

| 人群 | 场景 | 它解决什么 |
|---|---|---|
| 正在比较 Offer 的人 | 两个 Offer 月薪差 2k，一个有 14 薪 + 12% 公积金，一个 16 薪但天天 10 点下班 | 综合年包、真实时薪、年通勤时间三个维度摆在一张表里，谁更值钱一眼看清 |
| 投简历总被卡的人 | 觉得简历还行，却总在初筛后没消息 | 把 JD 拆成关键词，覆盖率与缺失项量化；缺失项直接给「10 分钟上手」的速学卡片 |
| 面临裁员 / 协商离职的人 | 不知道自己该拿 N 还是 N+1，怕签字吃亏 | 按第 47 条算到月，含高收入封顶、代通知金、2N 情形，附谈判提示 |
| 年终奖即将发放的人 | 听说「多发一元少拿千元」，不知道自己的金额是否踩坑 | 两种计税方式对比 + 6 个无效区间自动检测，直接给出最优金额 |
| 面试屡战屡败的人 | 每次被问住就过去了，下次还错在同一个点 | 复盘按类别自动归档成跨公司错题本，导出文档标出高频薄弱点 |



## 使用示例

### 1. 四步算清一个 Offer

| 步骤 | 操作 | 说明 |
|---|---|---|
| ① 填 | Offer 对比 → 月薪 / 月数 / 年终奖 / 公积金比例 / 期权折算 / 加班 / 通勤 | 最多 4 个 Offer，填完自动存本机 |
| ② 比 | 点「开始对比」 | 综合年包排序 + 条形图 + 差额结论 |
| ③ 看 | 「最优」徽章那列 | 同时看时薪：总包高但加班 20h 的，时薪可能更低 |
| ④ 判 | 底部决策提示 | 期权按 0 估值也不亏的 Offer 才更稳 |

### 2. 示例输出（补偿计算）

```text
入职 2020-03-10 · 离职 2026-09-20 · 月均应发 25000 · 情形：无过失性辞退（N+1）

工龄 6 年 6 个月（折算 7 个月）
经济补偿 7 × 25,000 = ¥175,000
代通知金（未提前 30 日通知）= ¥25,000
合计 ¥200,000
```

> 月工资超过当地社平 3 倍的，基数按 3 倍封顶、年限最长 12 年；填了社平工资，页面会自动判断是否封顶。

### 3. 常见问题

- **算出来比 HR 说的多/少**：先核对「月均应发」是否含奖金津贴（不是基本工资），再确认当地社平工资口径；封顶只对高收入者生效
- **年终奖建议金额为什么比我要的少**：那是无效区间上沿，多发一元会跳档，到手反而少；页面会给出「拿多少最划算」
- **JD 分析没识别出某个词**：内置词库覆盖常见技术栈，未收录的词会走通用学习框架；也可以在 Issue 里贴 JD，我把它加进词库
- **换电脑数据没了**：数据存在浏览器 localStorage，不跨设备同步、不上传（隐私设计）；迁移用底部「💾 数据备份」导出 JSON，在新设备导入即可

## 工作原理

### 1. 纯前端 + 纯函数计算

所有计算收敛在四个纯函数里（`compMonths` / `nOfM` / `bonusTaxInfo` / `offerCalc`），界面只做取值与渲染。这样同一份逻辑能被页面自检、Node 测试同时复用，不存在「测试一套、页面另一套」的口径漂移。

### 2. 三个计算口径

| 计算 | 依据 | 关键规则 |
|---|---|---|
| 工龄 → N | 《劳动合同法》第 47 条 | 每满 1 年 1 个月；满 6 个月不满 1 年按 1 年；不满 6 个月半个月 |
| 高收入封顶 | 第 47 条第 2 款 | 月工资 > 当地社平 3 倍 → 基数按 3 倍、年限 ≤ 12 年 |
| 年终奖单独计税 | 财政部税务总局公告（延续至 2027-12-31） | 奖金 ÷ 12 查**月度税率表**，再按全额计税；无效区间由税率表推导，不是硬编码结论 |
| 并入综合所得 | 个人所得税法 | 年表七级超额累进，起征点 6 万/年 |

### 3. 测试即证明

`tests/calc.test.js` 不在测试里重写算法，而是**从 `offer-compass.html` 抽出内联脚本**，在最小 DOM 桩上执行，再对真实函数做断言。120 项覆盖：工龄（含闰年、差一天不满整年）、N 的 0.5/1/多档、年终奖各档税额、无效区间自洽、综合所得税率表、Offer 年化、JD 词频、复盘分类、知识库完整性、脏输入守卫、示例数据的叙事结论、简历体检打分与改写。

`tests/structure.test.js` 补另一面——**点得动**：47 项静态断言检查 onclick 绑定的函数是否已定义、getElementById 引用的 id 是否存在、标签与面板是否一一对应、八个面板是否都有真实动作、13 个关键能力入口是否都在。这类错误不会报语法错，只会在用户点下去时静默失效。

> 这套测试上线时抓到一个真 bug：单独计税误用年度税率表，96000 的年终奖被算成 3%（应为 10%，9390 元）。已修复并留了回归断言。

### 4. 「宁可留空，不给看起来正确的错数字」

- JD 里没收录的关键词 → 通用学习框架，不编造技术细节
- 没填社平工资 → 不猜封顶，只提示「可能触发封顶，建议填写」
- 复盘分类拿不准 → 归入「其他」，不强行塞进某个类别

## 接口与数据格式

本项目没有后端接口，对外契约是**本地存储键**与**备份文件格式**两样。

| 存储键 | 内容 | 结构 |
|---|---|---|
| `wdc_offers_v1` | Offer 对比 | 数组 `{name,sal,mon,bon,fund,eq,ot,cm}`（原样存字符串） |
| `wdc_interviews_v1` | 面试复盘 | 数组 `{co,pos,date,round,cat,q[],note,ts}` |
| `wdc_resume_v1` | 简历文本 | 字符串 |
| `wdc_jd_v1` | 最近一份 JD | 字符串 |

备份文件（底部「💾 数据备份」导出）：

```json
{
  "app": "wdc-backup",
  "version": 1,
  "exportedAt": "2026-10-22T01:20:00.000Z",
  "data": { "wdc_offers_v1": "[...]", "wdc_resume_v1": "..." }
}
```

导入时依次校验 JSON 可解析 → `app` 标识匹配 → `data` 存在，任一不符则拒绝且**不写入任何键**。
完整字段说明与计算公式见 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。

## 边界与合规

1. **不构成专业意见**。补偿与税务结果为通用规则估算，各地执行口径有差异，重大决策请咨询律师 / 税务师。
2. **不采集任何数据**。无后端、无埋点、无第三方脚本；简历、Offer、面试记录只写进本机 localStorage，清浏览器数据即消失。需要迁移/留档时用「💾 数据备份」导出 JSON，文件在本机生成、由你自行保管。
3. **不代填、不代提交**。只做计算与清单，不涉及任何账号、支付、投递动作。
4. **政策时效**。年终奖单独计税政策执行至 2027-12-31；补偿规则依据现行《劳动合同法》。政策变动会在 README 与页面口径说明中同步。
5. **素材**。无第三方图片、字体、图标资源，视觉全部由 CSS 实现；不涉及任何商标素材。
6. **许可**。代码以 MIT 授权。
